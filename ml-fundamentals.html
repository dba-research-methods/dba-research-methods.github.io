The four paradigms

Every machine learning system falls into one of four families. They differ in one question only: what kind of signal the model learns from.

Supervised Learning

12 topics

Learn from labeled examples — inputs paired with correct answers. The workhorse of prediction.

Unsupervised Learning

8 topics

Find structure in unlabeled data — clusters, groups, and patterns no one told the model about.

Reinforcement Learning

6 topics

Learn by trial and error from a reward signal. Agents, policies, and delayed consequences.

Deep Learning

14 topics

Multi-layer neural networks that learn feature hierarchies directly from raw data.

The conceptual map

Ideas that unlock everything

Open glossary

Ten concepts, roughly in learning order. Each badge marks difficulty — start at Essential and work up.

01 Essential

Supervised vs. Unsupervised

The master division. Supervised models learn from labeled (X, y) pairs; unsupervised models hunt for hidden structure with no labels at all.

02 Essential

Overfitting

The model memorizes the training data instead of the underlying rule. Great on practice, embarrassing on new data — the #1 beginner trap.

03 Essential

Training vs. Inference

Training is where the model adjusts weights to reduce error. Inference is the fast, frozen moment when it makes predictions on new input.

04 Advanced

Gradient Descent

The optimization engine. Compute how the loss changes with each weight, then step downhill. Repeated, this finds the valley of low error.

05 Intermediate

Bias–Variance Tradeoff

Bias is systematic under-learning; variance is over-sensitivity to noise. Models straddle both — finding the balance is most of applied ML.

06 Essential

Cross-Validation

Split the data into folds and train on most while testing on the rest, rotating each time. Honest error estimates without wasted data.

07 Intermediate

Feature Engineering

Raw data rarely arrives ready to learn. Features are the transformed, measured properties a model actually sees — and their quality matters more than model choice.

08 Intermediate

Regularization

A tax on complexity. Regularizers gently discourage large weights, forcing simpler, more generalizable models in exchange for a bit of bias.

09 Advanced

Backpropagation

The chain rule, applied to networks. Errors flow backward through the layers so every weight knows exactly how much it contributed.

10 Advanced

The Representation

Neural networks learn their own internal representations — abstract feature hierarchies discovered from data, layer by layer, no human labels required for the features themselves.

The evidence map

Metrics that tell the truth

Accuracy alone is a lie on imbalanced data. Know which metric answers which question — and when a baseline beats your model.

Classification Start here

Accuracy, Precision, Recall

Accuracy = correct ÷ total. Precision = how many flagged are right. Recall = how many real cases we caught. When a class is rare, precision and recall matter far more.

Classification Threshold-free

F1 Score & ROC-AUC

F1 balances precision and recall in one number. ROC-AUC measures ranking quality across every decision threshold — robust to class imbalance.

Regression Start here

MSE, MAE, R²

Mean Squared Error punishes big misses. MAE reports average miss in raw units. R² says what fraction of variance your model explains.

Ranking Probabilistic

Log Loss

Punishes confident wrongness. A model that says 99% and is wrong gets hammered harder than one that says 55% — perfect for probability calibration.

Fraud / rare events Business-aware

Precision@k & Lift

When you can only act on the top k predictions, measure how many were correct and how much better than random that is. Directly ties to revenue.

Sanity check Always

The Baseline

Before celebrating, beat the dumbest reasonable guess: predict the majority class, the mean, or yesterday's value. Most "amazing models" barely clear it.

Dataset journal

Your first 6 weeks

A proven sequence, in order, without the detours. One step per week is comfortable; two is aggressive.

01

Set up your toolkit

Install Python + Jupyter, then numpy, pandas, scikit-learn, and matplotlib. Reproducibility beats flashiness from day one.

02

Learn the vocabulary

Work through the conceptual map above. If you can explain overfitting to a friend, you're ahead of most course graduates.

03

Train your first model

Linear regression on a toy dataset, end to end: split, train, predict, score. Do it by hand once — with sklearn, not by hand — then read every line.

04

Diagnose overfitting

Train a decision tree deep enough to memorize the data. Watch training score soar while validation score flatlines. This one experiment teaches more than any lecture.

05

Evaluate honestly

Add cross-validation and the right metric for your problem. Establish a baseline before you ever build anything clever.

06

Ship a portfolio project

A real dataset, a real question, a documented pipeline, and an honest error analysis. One finished project beats ten half-finished courses.

Reference

Glossary

Twelve terms in plain English. Expand any card for the one-line formal definition.

featureFeature

A measurable property of an input — the columns your model actually reads. Better features beat better models.

labelLabel

The ground-truth answer attached to an example, used only in supervised learning. The model's job is to predict it.

lossLoss function

A number scoring how wrong the model is. Training is the process of making this number as small as possible.

hyperparameterHyperparameter

A dial set before training starts — tree depth, learning rate, cluster count. Tuned separately from the weights the model learns.

epochEpoch

One full pass of the training data through the model. Multiple epochs let the model keep improving — and eventually overfitting.

train / val / testData split

Training set teaches, validation set tunes, test set — touched last — proves the model generalizes. Contamination ruins all three.
